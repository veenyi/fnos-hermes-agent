## 一、生命周期脚本（/var/apps/{appname}/cmd/）

| 脚本 | 语义 | 调用时机 |
|---|---|---|
| `install_init` | 安装前准备/检查 | 应用包文件落盘**之前** |
| `install_callback` | 安装后初始化（生成配置、建目录等） | 应用包文件落盘**之后** |
| `main` | 运行控制：`start` / `stop` / `status` | 启动/停止/状态查询 |
| `upgrade_init` | 升级前准备 | 新包覆盖前 |
| `upgrade_callback` | 升级后处理（数据/配置迁移、兼容性检查） | 新包覆盖后 |
| `uninstall_init` | 卸载前清理 | 移除已安装文件前 |
| `uninstall_callback` | 卸载清理后收尾 | 移除已安装文件后 |
| `config_init` | 配置变更应用前 | 更新配置变量前 |
| `config_callback` | 配置变更应用后（重启服务、通知进程等） | 更新配置变量后 |

**可重复执行（幂等）**：所有脚本应具备幂等性；安装、升级、配置流程都可能被重新执行。

**cmd/main 契约**：`start`/`stop`/`status` 三个子命令，其余返回 `exit 1`。退出码：`0`=成功（status 中表示运行中）、`1`=失败、`3`=status 中未运行。静态应用可在 manifest 设 `ctl_stop=false` 隐藏启停控制。Docker 应用 main 通常 `exit 0`，但 status 必须准确（`docker inspect <container> | grep -q '"Status": "running"'`）。

**用户可见错误**：脚本非零退出前，把简短可执行的错误信息写入 `$TRIM_TEMP_LOGFILE`（会展示给用户）。

## 二、流程链

- 安装：`install_init` → 应用包文件 → `install_callback`（首次启动前检查/初始化放这里）
- 升级：`upgrade_init` → 新包 → `upgrade_callback`（数据/配置迁移、兼容性检查；运行中系统可能先停后启）
- 卸载：`uninstall_init` → 移除已安装文件 → `uninstall_callback`（尊重用户数据；可配合 wizard/uninstall 收集"保留/删除数据"）
- 配置：`config_init` → 更新配置变量 → `config_callback`

## 三、Manifest（包根目录，无扩展名，INI）

- `appname`（唯一标识=安装目录 `/var/apps/{appname}`）、`version`、`display_name`、`desc`（可 HTML）、`source`（第三方 `thirdparty`）
- `platform`：`x86`/`arm`/`all`；`os_min_version`/`os_max_version`；`ctl_stop`（false 隐藏启停）
- `install_type`：空=安装时选存储位置，`root`=系统分区
- `install_dep_apps`：依赖应用 `:` 分隔，`>` 最低版本（如 `database>2.2.2:cache`）
- `desktop_uidir`（UI 目录，默认 ui）、`desktop_applaunchname`（多入口默认打开）
- `service_port`、`checkport`（启动前查端口，默认 true）
- `disable_authorization_path`：false=用户可配置授权目录
- `micro_app=true`：调用 JS SDK 必填声明，否则页面不按微应用加载

## 四、环境变量 TRIM_* 全集

安装后目录（用变量非硬编码）：`/var/apps/{appname}` 下 `target→/vol{n}/@appcenter/{appname}`、`etc→@appconf`、`var→@appdata`、`tmp→@apptemp`、`home→@apphome`、`meta`、`shares/`、`cmd/`、`wizard/`。

- 应用信息：`TRIM_APPNAME`、`TRIM_APPVER`、`TRIM_OLD_APPVER`（升级旧版）、`TRIM_APP_STATUS`（INSTALL/START/UPGRADE/UNINSTALL/STOP/CONFIG）
- 路径：`TRIM_APPDEST`（target）、`TRIM_PKGETC`、`TRIM_PKGVAR`、`TRIM_PKGTMP`、`TRIM_PKGHOME`、`TRIM_PKGMETA`、`TRIM_APPDEST_VOL`
- 用户：`TRIM_USERNAME/GROUPNAME/UID/GID`（应用用户）、`TRIM_RUN_USERNAME/GROUPNAME/UID/GID`（脚本实际执行用户，特权操作可与前者不同）
- 网络/资源：`TRIM_SERVICE_PORT`、`TRIM_DATA_SHARE_PATHS`（data-share，`:` 分隔，也可经 `/var/apps/{appname}/share/` 软链）、`TRIM_DATA_ACCESSIBLE_PATHS`（用户授权路径）
- API 认证：`TRIM_API_TOKEN`（开放 API token，勿持久化/暴露前端）
- 日志/临时：`TRIM_TEMP_LOGFILE`（用户可见错误）、`TRIM_TEMP_UPGRADE_FOLDER`、`TRIM_PKGINST_TEMP_DIR`、`TRIM_TEMP_TPKFILE`
- 系统：`TRIM_SYS_VERSION/_MAJOR/_MINOR/_BUILD`、`TRIM_SYS_ARCH`、`TRIM_KERNEL_VERSION`、`TRIM_SYS_MACHINE_ID`、`TRIM_SYS_LANGUAGE`
- 向导变量：向导收集值直接成为**同名环境变量（无 TRIM_ 前缀）**，自定义用 `wizard_` 前缀

## 五、权限模型（config/privilege JSON）

```json
{ "defaults": { "run-as": "package" }, "username": "myapp_user", "groupname": "myapp_group", "join-groups": ["video","render"] }
```
- `run-as: package`（默认推荐）：专用应用用户，与系统隔离；省略 username/groupname 按 appname 生成
- `join-groups`：加入附加系统组（video/render 等访问 GPU/硬件），按需最小化
- `run-as: root`：仅生命周期脚本特权准备用；长期进程须 `runuser -u "$TRIM_USERNAME" -- ...` 降权
- 用户文件访问：默认无广泛权限；两种授权——应用设置里授权目录 或 `config/resource` 声明 `data-share`。共享目录用 **Windows ACL 模型（非 POSIX ACL）**；可选 `permission` 字段（rw/ro 用户列表）
- `usr-local-linker`：bin→/usr/local/bin、lib→/usr/local/lib、etc→/usr/local/etc；命令名带应用标识避免冲突

## 六、统一网关

- `app/ui/config` `.url` 用 `gatewayPrefix`+`gatewaySocket` 声明（protocol/port 忽略）
- 流程：注册路径 → 服务监听 gatewaySocket 的 Unix Socket → 用户开 `/app/myapp` → 系统校验会话 → 转发 socket → 应用读用户 Header
- `gatewayPrefix`：`/app/{appname}` 或带 customPath；`gatewaySocket` 只填文件名（在 target 目录，用 `${TRIM_APPDEST}` 定位）
- 转发用户 Header（可信身份）：`X-Trim-Userid`、`X-Trim-Isadmin`（true/false）、`X-Trim-Username`。**不要信任客户端传的用户 ID**
- WebSocket：复用前缀+Socket，推荐子路径 `/app/myapp/ws`，前端 `ws:`/`wss:` 拼接
- Docker 应用：挂载 `${TRIM_APPDEST}` 进容器（如 `/app/target:rw`），容器内监听 `/app/target/app.sock`
- vs index.cgi：cgi 每次请求起进程、不支持 WS、路径 `/cgi/ThirdParty/{appname}/index.cgi/`；网关常驻、支持 WS、给用户 Header

## 七、appcenter-cli 与 fnpack

- **appcenter-cli**（设备端）：`install-fpk myapp.fpk`（向导用 `--env config.env`，敏感勿入库）、`install-local`、`default-volume [n]`、`list`、`start/stop myapp`
- **fnpack**（V1.2.3，下载 static2.fnnas.com/fnpack/）：`fnpack create`、`--template docker`、`--without-ui true`、`build`、`build --directory <path>`
- 打包前校验：manifest 必要字段、config/privilege 合法 JSON、config/resource 合法 JSON、ICON.PNG(64)+ICON_256.PNG(256)、app/cmd/wizard 存在、声明 desktop_uidir 时 app/{dir} 存在。图标 PNG/JPG、sRGB、≤1024KB

## 八、开放 API（系统 ≥1.2.0401，App ≥1.34.0）

- 接入：`config/resource` 声明 `api-scope`（trim.file.sharedAccess/userAccess/userAcl/path、trim.system.getPlatformConfig）；JS SDK 须 `micro_app=true`
- 前端 JS SDK（`@trimjs/web-app`，`new TrimApp()`）：`isWeb`/`isStandaloneWeb` 环境判断；宿主内直调 `pickSharedFile`/`pickUserFile`；独立浏览器 `openAppAuth(method, params, {target, features})` + `redirectUri` + `createAuthState()` 防伪造 + `parseAppAuthCallback` 校验 + `postMessage` 通知 + `window.close()`
- 后端 API：统一 `POST /api/v1/trimapp`，**只能经 Unix Socket `/var/run/trim_open_gateway_apiscope.socket` 调用**，`Authorization: Bearer <TRIM_API_TOKEN>`。请求 `{reqId, req, appName, data}`，响应 `{reqId, code, msg, data}`，`code=0` 成功
- 共享授权路径（仅管理员，只目录）：`trim.file.getSharedAccessibleFolders`（返回 `data.paths[]`）、`trim.file.delSharedAccessibleFolder`（`{path}`→`{suc:true}`）
- 用户授权路径（结合网关按 uid）：`trim.file.getUserAccessibleFolders`（`{uid}`，**只返回目录**）、`trim.file.delUserAccessibleFolder`（`{uid,path}`）
- 文件权限检查：`trim.file.checkUserACL`（`{uid, path}` 单值或数组 → `[{path, readable, writable, deletable}]`；不存在/无权三项 false）。授权只解决应用用户 ACL，返回前仍按当前 uid 检查
- 路径转换：`trim.file.convertPath`（`{path, language}`，**language 必填** → `semanticPath` 如 `/vol1/1000/photo` → `存储空间1/admin 的文件/photo`）。页面勿直接展示 /vol1/
- 页面路由（前端无 scope）：`openFile(path)`、`showFileDetails(paths[])`、`openFileManager(path)`、`openAppSetting()`、`openURL(url,target?,features?)`
- 页面交互：`setTitle(title)`、`$on('os/theme'|'os/language')`（仅 Web 宿主）、`setExitPageTips`、`close()`
- 平台配置：前端 `getPlatformConfig()` → `{theme, language, systemLanguage?, appVersion?, systemVersion, format}`；后端 `trim.system.getPlatformConfig` → `{systemLanguage, systemVersion}`
- 错误码：JSSDK `1000000` 内部异常 / `1000001` 登录失败 / `1000002` 权限不足 / `1000030` 请求不合法 / `1000300` 应用未安装 / `1000701` 路径不存在 / `1003103` 权限校验失败 / `1003201` 管理员关闭授权；后端 `401+200004` Unauthorized / `403+200003` Forbidden / `404+200005` Not Found / `500+200006` Internal

## 九、依赖/中间件/运行时

- `install_dep_apps=database:cache` **从右到左**安装/启用；嵌套依赖不递归，直接依赖都须显式声明
- 中间件：`redis`（127.0.0.1:6379，独立 db/key 前缀）、`minio`（127.0.0.1:9000，凭据勿硬编码）、`rabbitmq`（127.0.0.1:5672）
- 运行时（用前加入 PATH）：`python312`→/var/apps/python312/target/bin、`nodejs_v22`→/var/apps/nodejs_v22/target/bin、`java-21-openjdk`→/var/apps/java-21-openjdk/target/bin

## 十、用户向导（wizard）

- 四文件：`wizard/install`、`upgrade`、`uninstall`、`config`
- JSON 数组，每步 `{stepTitle, items:[{type, field, label, initValue, options, rules}]}`；`field` 名=环境变量名
- 类型：text/password/radio/checkbox/select/switch/tips（helpText）
- 校验：`required`、`min`/`max`、`len`、`pattern`
- 命名：字段名稳定、自定义 `wizard_` 前缀、**禁用 TRIM_ 前缀**；密钥不写日志；入口配置可引用 `${wizard_port}` 等
